# 110 Profile 全部博主统计设计

## 目的

在手机号为 `110` 的超级管理员可见的“合作博主优惠码统计”中，增加一次查看全部博主有效数据的能力，避免管理员逐个选择博主查询。

## 交互

- 在“合作博主”选择框旁增加“全部统计”复选框。
- 勾选后，清空并禁用具体博主选择框；取消勾选后恢复单博主选择。
- 月份和“全部时间”筛选保持现有行为。
- 点击“查询”后：
  - 单博主模式继续展示现有单份统计结果。
  - 全部统计模式展示多张博主卡片。
- 页面以桌面 Web 为主；平板和手机只保证内容不溢出且基本可操作，不做单独视觉方案。

## 聚合规则

- 以 `organization_name` 作为博主聚合键。
- 同一 `organization_name` 下的所有 `campaign_name` 合并计算，兑换、购买、人数和金额不得重复统计。
- 卡片标题列出该博主名下实际参与统计的活动名称，以 ` / ` 分隔，例如：`花虫二 / 花虫二-其他批次`。
- 在所选时间范围内，只要博主存在兑换记录或购买记录，就展示该卡片。
- 在所选时间范围内兑换和购买均为零的博主不展示。
- 不增加跨博主的总计卡片。

## 卡片内容

每张卡片沿用当前单博主结果的信息：

- 兑换次数、兑换人数
- 购买订单、购买人数
- 订单原价、优惠金额、实付金额
- 该博主在筛选时间内的购买明细

## 实现方案

扩展现有统计接口，使其同时支持单博主和全部统计模式。全部统计由后端一次完成按 `organization_name` 的聚合，并返回每组对应的活动名称列表和现有统计字段。前端根据查询模式渲染单份结果或多张博主卡片。

未采用的方案：

- 前端逐个请求并合并：请求数量随博主增加，且容易因现有名称包含匹配造成重复统计。
- 新建独立接口：会与现有统计接口产生不必要的重复逻辑。

## 约束与非目标

- 不改变现有权限：仍仅对手机号 `110` 的超级管理员开放。
- 不改变现有单博主查询的统计字段和用户可见内容。
- 不增加新的依赖。
- 不在本次工作中重新设计整个 Profile 页面或移动端界面。

## 验收标准

- “全部统计”与具体博主选择互斥，切换状态正确。
- 月份和全部时间在两种查询模式中都有效。
- 相同 `organization_name` 的多个活动只生成一张卡片，标题完整列出其活动名称。
- 汇总数字和购买明细严格限定在所选时间内，且不存在跨组或重复计算。
- 只有存在兑换或购买的博主被返回和展示。
- 单博主模式及现有权限控制继续通过测试。
- 桌面端显示自然；较窄屏幕没有明显横向溢出或无法操作的问题。
